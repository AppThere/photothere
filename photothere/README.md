# PhotoThere

A Kotlin Multiplatform (Compose) front end for the PhotoCraft engine, built the way Loki Text is built
for WordCraft: a thin UI that runs the engine's commands by id over a six-function C ABI. It is
separate from the egui front end (`crates/ui-egui`) and shares only the Rust engine.

```
Compose UI (app/, Kotlin, on Loki Kit)  ──  JSON commands  ──  C ABI (JNA)  ──  loki-ffi (ffi/, Rust)  ──  photocraft_automation::Headless (`trusted_local`)
```

How it was made, and how to continue: Loki Text's
[playbook](https://github.com/AppThere/loki-text/blob/main/loki-text/docs/kmp-responsive-ui-playbook.md)
and [`egui2compose`](https://github.com/AppThere/loki-text/blob/main/loki-text/docs/egui2compose.md)
(in the `loki-text/` folder of the WordCraft fork). Phases 1–4 are done here, and phase 5 is started.

## The window

As on the desktop, not a ribbon: dark at the start, a text menu bar with every engine command, an
options bar, a column of tools, the canvas under its document tab, a dock of panels with an icon
strip, and a status bar. App-specific: the desktop's tool palette in its slots (alternates on a long press or right click), the foreground and background colours with swap and reset, brush size and hardness in the options bar, and the Properties, Layers (show, hide, select, new, duplicate, delete), Channels and History panels. On a phone the tools and the panel icons share a
row under the canvas and a panel opens over its lower half. It is the kit's `CanvasWorkspace`; this
app's parts are in `AppParts.kt`.

## The canvas

On Android 10 and later a painting stroke's ink goes straight to the display's front buffer as
the pen moves (Loki Kit's `InkLayer`), a frame or two ahead of the app's own drawing, and stays
until the engine's picture of the stroke is on screen.


Every tool of the palette that has an engine command works on the canvas, with a mouse, a finger
or a pen:

* **Painting** (Brush, Pencil, Mixer Brush, Eraser, the stamps, healing, Blur/Sharpen/Smudge,
  Dodge/Burn/Sponge, History Brush): the stroke is drawn at once as wet ink, with its width and
  opacity following the pen when the brush's **Pressure: size** / **Pressure: opacity** are on (the
  options bar), and sent to the engine whole when the pen lifts (`paint.stroke` and the like, with
  each point's pressure, tilt and time). A pen's **eraser end** erases whatever tool is in hand; its
  **side button** (an S Pen's) samples a colour.
* **Selecting**: marquees (Shift adds, Alt subtracts), lassos, Quick Selection, Object Selection,
  Magic Wand. **Crop**, **Move**, **Gradient**, **Paint Bucket**, **Magic Eraser**, **Red Eye**,
  **Eyedropper**, the **shape** tools and **Line**, **Type** (places text; typing on the canvas is
  not built yet), **Hand** and **Zoom**.
* **Navigation**: two fingers pan and pinch; Ctrl+wheel zooms, the wheel scrolls; the zoom pill at
  the bottom left zooms and fits. Once a pen has touched the canvas a finger no longer paints (palm
  rejection); before that a finger paints, for a phone with no pen.

**Type** opens a text field where it is tapped (on a tablet or phone, the on-screen keyboard), or
over the text it is tapped on, to edit it. The **Pen** tools build the work path: a tap adds a
corner, a drag pulls out smooth handles, a tap on the first point closes it (or Done in the
options bar); Freeform Pen draws it, Curvature Pen smooths it, Direct Selection drags its anchors,
and with a work path the options bar offers Selection, Fill, Stroke and Delete. The selection
shows as **marching ants**, traced from the engine's selection mask (`loki.selectionOutline`).

**File** has Open…, Save, Save As… and Export as PNG… (the desktop's own commands, which the
engine has on no menu); on Android, Open and Save As use the system's document pickers, and Save
writes back to the file that was opened.

On a **phone or tablet** the menus open from one button as a sheet (from the bottom on a phone,
from the side on a tablet), and the document's title opens File.

Not yet: pen tilt on the desktop and iOS (Android
reads it), and the path tools' finer behaviours (adding and deleting anchors on a path,
converting points).

## Layout

- `Cargo.toml`, `ffi/`: its own Cargo workspace (the engine workspace forbids `unsafe`; the FFI
  crate needs it). Depends on `../crates/*` by path. `ffi/src/lib.rs` is the same in every Craft
  front end of this kind; `ffi/src/app.rs` is what is PhotoCraft's own. Header: `ffi/include/loki.h`.
- `app/`: the Gradle project generated by `egui2compose.py` from the egui front end, on Loki Kit
  (`app.loki:kit`, included from `../../loki-text/loki-text`, so the WordCraft fork must be
  checked out beside this repository). `jnaMain` has the JNA binding (`NativeEngine.kt`) for the desktop
  and Android, `commonMain` the surface (`EngineSurface.kt`), `androidMain` the activity.
- `REPORT.md`: what the generator read from the egui front end and what it could not translate
  (rerunning it also writes `ui-model.json`, everything it read, which is not kept).

## Run

```sh
scripts/build-desktop.sh run          # cargo build --release -p loki-ffi, then gradle :app:run
VARIANT=Release scripts/build-android.sh   # libloki_ffi.so for arm64-v8a and x86_64, then the APK
adb install -r app/build/outputs/apk/release/app-release.apk
cargo test -p loki-ffi                # the C ABI: hostile arguments, command state, surface, fixture
gradle :app:jvmTest                   # the coverage test: every engine command has a way to it
LOKI_SHOTS=/tmp/shots gradle :app:jvmTest --tests '*CoverageTest*' --rerun   # phone, tablet, desktop PNGs on the real engine
```

Use Gradle 8.14 or 9.1 with JDK 21 (see the playbook's pitfalls). Without the native library the
app still opens, on the recorded command list, and nothing executes.

After an engine change: `LOKI_UPDATE_FIXTURES=1 cargo test -p loki-ffi kotlin_command_fixture`,
then `gradle :app:jvmTest`.

## Status (November 2026)

Built against the ArtCraft release PhotoCraft v0.23.1. Verified on Linux x86_64, JVM desktop:

- `cargo test -p loki-ffi --release`: 6 tests, including that a new session opens a document that renders (`a_new_session_has_a_document_that_renders`).
- `gradle :app:jvmTest`: the coverage test passes against the engine's own list of 1009 commands.
- Off-screen renders at 390, 800 and 1280 dp with the real engine library: the command bar from
  `engine.commands` and the surface.

The surface: `documents`: each open document's composite (`photocraft_compose::thumbnail`, at most 1:1), in a scrolling column fitted to the width.

Not done (the work that is left, in the playbook's order):

- **Command state and requests** (phase 6). `loki.commandState` reports disabled commands from
  the engine's own checks; `on` (toggles) is empty, and `loki.uiRequests` is always empty because
  the headless backend handles or drops requests itself.
- **Dialogs**: the translated dialogs have the desktop's layout but guessed parameter names (see
  `REPORT.md`); the kit's generated form (`CommandFormDialog`) is right by construction and is
  what the command bar opens.
- **Android**: one APK for arm64-v8a (phones, tablets, ARM Chromebooks) and x86_64 (Intel
  Chromebooks). The release build is signed with the debug key so it installs on one's own devices;
  distribution needs a real key, and R8 is off until JNA has keep rules. Open copies the chosen file
  into app storage; saving writes to the app's own Documents folder (no Save As picker yet).
- **iOS** (phase 9): not started.

## Rules

The repository's rules hold here: never crash (the FFI layer catches panics and returns errors;
the Kotlin side degrades on a bad reply), and no Microsoft, Adobe, Avid or Autodesk assets. No
asset files are added; the Lucide icons are a dependency (ISC).
